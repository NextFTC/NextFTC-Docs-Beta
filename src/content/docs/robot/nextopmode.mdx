Every OpMode you write with NextFTC should xtend `NextOpMode`.
NextFTC runs it inside a `LinearOpMode` for you,
passes in your [`NextRobot`](/robot/nextrobot/),
and ticks the command scheduler and [triggers](/robot/triggers/) every loop.

## Fields

`gamepad1` and `gamepad2` are the SDK's `Gamepad` objects, `telemetry` is the SDK's `Telemetry`,
and `hardwareMap` is the SDK's `HardwareMap`.
All four are plain fields on the class, so use them directly.

## Lifecycle

Every one of these is optional.
Override the ones you need:

| Method                     | Called                                                 |
| -------------------------- | ------------------------------------------------------ |
| `disabledPeriodic()`       | Repeatedly, while the Driver Station is in INIT.       |
| `start()`                  | Once, right after the PLAY button is pressed.          |
| `periodic()`               | Repeatedly, while the OpMode is running.               |
| `end()`                    | Once, when the OpMode finishes.                        |
| `onControlHubBulkData()`   | Repeatedly, when the BulkReadHook produces data.       |
| `onExpansionHubBulkData()` | Repeatedly, when the BulkReadHook produces data.       |
| `onLocalizationData()`     | Repeatedly, when the PinpointHook produces data. (WIP) |

<Tabs syncKey="language">
<TabItem label="Kotlin">

```kotlin
@NextTeleop(name = "My Teleop")
class MyTeleop(robot: MyRobot) : NextOpMode(robot) {
    override fun periodic() {
        Telemetry.log("Status", "Running")
    }

    //Optional. Don't override or return false to disable Blaze.
    override fun enableBlaze() = true
}
```

</TabItem>
<TabItem label="Java">

```java
@NextTeleop(name = "My Teleop")
public class MyTeleop extends NextOpMode {
    public MyTeleop(MyRobot robot) { super(robot); }

    @Override
    public void periodic() {
        Telemetry.log("Status", "Running");
    }

    //Optional: Don't override or return false to disable Blaze.
    @Override
    public boolean enableBlaze() {
        return true;
    }
}
```

</TabItem>
</Tabs>

Take your `NextRobot` as a constructor parameter and pass it straight to `super(...)`.
NextFTC's scanner builds your OpMode and passes in the robot it found,
so `new MyRobot()` never appears in your code.
See [robot project structure](/robot/project-structure/) for the exact rules.

### Initialization

Unlike the FTC SDK, the NextFTC OpMode class doesn't have an `init()` or `init_loop()` method.
Instead, when you press the INIT button on the Driver Station, the OpMode is constructed.
Then `disabledPeriodic()` is called every loop until you press PLAY.
Things that would have been in `init()` can be moved to the OpMode constructor,
including any `hardwareMap` lookups.

Gamepad and trigger bindings can be registered in either the constructor or `start()`.

## What runs every loop without you

Four things happen on every iteration, none of which you call yourself:

- `periodic()` on your `NextRobot`, then on each of its mechanisms.
- Trigger polling and `Scheduler.execute()`, which is what makes bound commands run.
- A tick of the motor control loops.
- A telemetry flush.

## `BulkReadHook`

Bulk-reading your control and expansion hubs is the one piece that isn't automatic.
Pass `BulkReadHook` as an extra constructor argument.
It puts every Lynx module in manual bulk-caching mode at start and clears the cache at the end of each loop,
so each loop reads fresh data with one round trip per hub instead of one per device:

<Tabs syncKey="language">
<TabItem label="Kotlin">

```kotlin
class MyTeleop(robot: MyRobot) : NextOpMode(robot, BulkReadHook)
```

</TabItem>
<TabItem label="Java">

```java
public class MyTeleop extends NextOpMode {
    public MyTeleop(MyRobot robot) { super(robot, BulkReadHook.INSTANCE); }
}
```

</TabItem>
</Tabs>

## `BlazeBulkReadHook`

Using the BlazeFTC library, it is possible to run your code at a much higher speed than is typically possible.
On the Control Hub or on a USB Expansion Hub, a slow mode hook can easily provide data at 500 hz. 
For more information on how that works, check out the [BlazeFTC Readme](https://github.com/owenpmckenna/blaze_ftc).
To take advantage of this project using NextFTC, use the following setup:

<Tabs syncKey="language">
<TabItem label="Kotlin">

```kotlin
class MyTeleop(robot: MyRobot) : NextOpMode(robot, BlazeBulkReadHook(Type.EXPANSION_HUB, false)) {
    //Must be enabled for hook to work
    override fun enableBlaze() = true
    override fun onExpansionHubBulkData() {
        //Run PID loops here
    }
}
```

</TabItem>
<TabItem label="Java">

```java
public class MyTeleop extends NextOpMode {
    public MyTeleop(MyRobot robot) { super(robot, new BlazeBulkReadHook(Type.EXPANSION_HUB, false)); }

    //Must be enabled for hook to work
    @Override
    public boolean enableBlaze() {
        return true;
    }
    @Override
    public void onExpansionHubBulkData() {
        //Run PID loops here
    }
}
```

</TabItem>
</Tabs>


## Registering with the Driver Station

Annotate your class with `@NextTeleop`, `@NextAutonomous`, or `@NextUtility` to make it
selectable on the Driver Station.
NextFTC picks these up the same way the SDK picks up `@TeleOp` and `@Autonomous`.
See [robot project structure](/robot/project-structure/) for how the scan works.

<Aside type="note">
  `@NextTeleop(name, group)` and `@NextAutonomous(name, group, preselectTeleop)`
  both default `name` to the class name. `group` defaults to `"NextFTC Teleop"`
  or `"NextFTC Auto"` respectively. `preselectTeleop` lets an autonomous OpMode
  suggest which teleop the Driver Station should switch to afterward.
  `@NextUtility(name, description)` registers a utility OpMode instead.
</Aside>
